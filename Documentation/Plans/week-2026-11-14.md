## Scripting C1: past 16 arguments a call is refused, never made with arguments dropped (2026-11-14)

- **Fixed:** an AngelScript call carries at most 16 arguments (`kMaxArgs`, fixed arrays, so a call
  allocates nothing). A native method or constructor past it was bound anyway and called with its
  last arguments dropped (a warning in the log); a script function past it was called the same way
  from native code. A native function past the limit is not bound (`FitsCall`: one error naming
  it), so a script using it does not compile; calling a script function past it fails with
  "'f' takes N parameters; a call carries at most 16". The dispatch truncations are refusals that
  should not be reached. Luau collects arguments in an array and has no limit.
- **Tested:** Script.AngelScript.Tests (a 17-parameter native method does not compile while a
  2-parameter one does; a 17-parameter script function called from native code is refused and
  said). With the limit taken out, the use compiles and the call runs.

## Scripting C1: a breakpoint inside an AngelScript coroutine hits (2026-11-14)

- **Fixed:** the debugger armed only `ExecuteCall`'s context, so a breakpoint in a coroutine's body
  never hit; Luau's did. A coroutine's context now takes the active debugger's line callback before
  each run (`ArmCoroutine`), so a debugger attached since it started sees it. A suspend the
  debugger adopted holds the coroutine (`held`: the scheduler skips it), and the debugger's Continue
  or step hands it back to the scheduler, not the context pool (`ReleaseHeldCoroutine`: kept if it
  waits again, reported and dropped if it ended). AngelScript honours `wait`'s suspend only after
  the next line begins, so the debugger skips the line a wait is leaving (`IsWaitSuspending`), or
  the coroutine broke before its wait was over. Cancelling a held coroutine lets the debugger go of
  it; a debugger destroyed while holding one drops it.
- **Tested:** the battery's `debugCoroutineModule`, in both backends: the breakpoint hits on its
  line when the scheduler resumes the coroutine, frames while paused do not run it on, and Continue
  finishes it. Without the arming, it never hits.
- **C1 is done.** Its items, with the findings that did not hold: Luau's `waitUntil` facades already
  reached their context.

## Scripting C2: `#include` is tracked (2026-11-14)

- **Fixed:** the cook's `CScriptBuilder` had no include callback, so an `#include` was read from disk

## Scripting C2: a replaced class's module goes when nothing runs it (2026-11-14)

- **Fixed:** each reload of a behaviour class loads a new AngelScript module beside the old one, and
  every old module stayed until the context closed. Discarding one resets its globals, which an
  instance made before the reload may still read, so a module is now discarded once a newer one
  declares every class it does and nothing runs its code: no live instance wrapper of its classes, no
  coroutine started in it or owned by one of its instances, no delegate into it, and no script call
  running (an instance can destroy its own entity mid-method). The check runs at each load and at
  each wrapper or delegate release. A module of free functions alone, or one with a class the newer
  does not declare, stays. What the count cannot see is an old-class object held only by script
  (passed into another script's field): after the discard, its reads of module globals fault, as a
  reported script exception. Luau needs nothing: the newer class table takes the global and the old
  one is collected.
- **Tested:** Script.AngelScript.Tests (a live old instance keeps its module and globals, its release
  discards it; a replaced module with no instance goes at once; one with another class stays), by
  the engine's module count; with retirement turned off both fail. Script.Luau.Tests: a replaced
  class table is kept while an instance holds it and collected after (Luau already behaved so).
  Clang and gcc: the script, engine script and game instance suites pass.

## Scripting C3: the call path (2026-11-14)

- **Changed:**
  - A method call: an AngelScript object built a `String` of the name and scanned its class's
    methods on every call; it now finds each method once and calls the function it found. Luau still
    looks the method up per call (a script may assign `self.onUpdate` at runtime, which a test holds)
    but pushes the name from the view instead of copying it.
  - AngelScript calls take their context from a pool (`SetContextCallbacks`, up to eight idle) instead
    of the library making and freeing one per call.
  - The run collected in full every frame. A frame now steps each collector for
    at most `ScriptBudget::collectSeconds` (0.5 ms), and a full collection runs when a scene stops or
    unloads and the run goes on. AngelScript's incremental mode always reports an unfinished cycle,
    so its step is bounded at about one step per tracked object (none when it tracks none); the first
    version, bounded only by time, spent the whole 500 us on every idle frame, which the benchmark
    showed. Luau steps only a cycle its own pacing started.
  - AngelScript's value boxes come from the manager's allocator (each box carries it, since the
    thunks that free boxes have no owner), so its script code no longer uses `DefaultAllocator()`.
  - The benchmark takes the manager's allocator, counts allocations through a `TrackingAllocator`,
    and times an idle frame's step and the longest frame while steps free 1000 cycles.
- **Measured** (RelWithDebInfo, clang, this box, three runs, against the C0 baseline):

  | Measure | AngelScript before | after | Luau before | after |
  |---|---|---|---|---|
  | A handler call | 428 ns | 260 to 274 ns | 231 ns | 210 to 232 ns |
  | Allocations per handler call | (not counted) | 0 | (not counted) | 0 |
  | A `math` iteration | 2327 ns | 2302 to 2376 ns | 725 ns | 763 to 790 ns |
  | Allocations per `math` iteration | (not counted) | 5 | (not counted) | 0 |
  | A frame's collector work, idle | 0.06 us (full) | 0.02 to 0.05 us (step) | 11.6 us (full) | 0.026 us (step) |
  | 1000 cycles of garbage: full collection | 398 us | 385 to 426 us | 35 us | 32 to 35 us |
  | The same, longest frame of steps | | 138 to 150 us | | 24 to 27 us |

  The math loop is C4's (values in script); its five AngelScript allocations per iteration are the
  boxes. Luau's math difference is within its run-to-run spread.
- **Tested:** Script.AngelScript.Tests (a method found once keeps its overloads apart and a missing one
  stays missing; one collector step leaves garbage, repeated steps free it all, which fails on the
  old code, where a step did nothing); Script.Luau.Tests (a method the instance assigns itself runs on
  the next call); the budget test already reuses a context after a budget stop and a stack overflow.
  Clang and gcc: Core (the allocator tripwire, its stale entry removed), the script, script pipeline,

## Scripting C4: plain types are values (2026-11-14)

- **Ruled** (user, 2026-11-14): values are implicit and identity is declared. The spec's "a flag
  from the traits" also made every component a value (seven on the surface: a light, a character,
  a nav agent), so a script would have edited a copy; a type whose value stands for one live thing
  declares `HasIdentity()` instead, which `ComponentMethods<T>` does. The script `Entity`, a facade,
  is a value as Sedulous's is; Luau keeps `nil` for "no entity".
- **Changed:**
  - Core: `TypeInfo::trivialCopy` from the traits, `hasIdentity` from the reflection, and

## Scripting C5: AngelScript's memory is capped (2026-11-14)

- **Fixed:** AngelScript allocated through malloc with no cap, so a script that grew without end
  took the machine's memory, where a Luau context refuses a block past its heap budget. The
  library takes one pair of memory functions for the process, installed once before the first
  engine: each block carries its size in a 16-byte header, the bytes held are counted, and a
  block that would pass the cap is refused, which the library reports as "Out of memory" in the
  call that asked. The cap is the heap budget an AngelScript manager last set (accepted with the
  spec: one for every AngelScript manager in the process). Like Luau's, the blocks come from the
  C allocator, counted and capped.
- **Tested:** Script.AngelScript.Tests: with a 64 MB budget, a call asking for 800 MB fails with
  "Out of memory" and the next call on the context runs; with the refusal turned off it does not
  fail. Clang and gcc.

## Scripting C2: a class's handlers come from the compiled class (2026-11-14)
