## Sockets are not inherited by a child process (2026-11-07)

- **The bug:** every socket the engine opened (UDP, TCP listen, connect and accept, on Linux and
  Windows) was inheritable, so a process it started got a copy: a file manager a "Show in folder"
  starts outlives the editor and kept its MCP port, and a later editor could not listen on it. Found
  on the Sedulous side (a relaunched editor's MCP port answered nothing).
- **The fix:** Linux opens each socket with `SOCK_CLOEXEC` and accepts with `accept4(...,
  SOCK_CLOEXEC)`; Windows clears `HANDLE_FLAG_INHERIT` on each socket it opens or accepts. Tested in
  Core.Tests: with a listener, a UDP socket, a connection and an accepted one open, a child shell
  finds none of their descriptors (Linux), and none is an inheritable handle (Windows).

## A scene page's Simulate is a run (2026-11-08)

- **The bug:** found on the flagship. A scene page's Simulate runs its level script, and the
  dialogue box it pushed stayed after the Simulate stopped; a later Play showed it over the run's
  own box until the editor restarted. A simulated scene had no run, so a script reached the GUI's
  shared tier through `gui::root()`, the tier every Game tab draws above its run's screens, and
  nothing took it down. First fixed with a tier of its own for run-less scripts and a count of the
  running simulations (f7ed8f464, e6e3bd1e8); replaced the same day by the cause's fix, below.
- **The ruling:** an editor scene page has a run (the user, 2026-11-08), reversing the run
  design's D11 (`Archive/run-context-history.md`: "an editor page's scene ... has no run"). All
  scene pages also shared one script host, so two pages simulating shared a context, a clock and
  module globals.
- **The script host keeps its scripts' clock:** `ScriptRunHost::Advance(dt)` (what `Time` reads,
  and the collector's step), which `GameInstance::DriveRunHost` and `ScriptSubsystem::Update` each
  copied; a run with no scripts advances an unread clock. The run's own clock (`run.realTime`)
  stays on the game's run.
- **A scene's behaviours run on its run's host:** `ScriptSubsystem::RunHostFor(scene)` asks the
  scene's run for its `ScriptRunHost` (a run registers it as a service) and falls back to the
  default host. `GameInstance::CreateScene` no longer re-binds by hand. The C++ samples that make
  scenes in the primary game's group now run their scripts on its host.
- **The page's run:** `SimulationRun` (Editor.Scene), owned by the page's `SceneSimulation` and
  living as long as the page, holds a script host and nothing a game has besides. Its scenes carry
  it and its bus (the page's own bus is gone); it joins the embedded app's runs
  (`DefaultApplication::Runs()` is now the `RunRegistry`); each Simulate is one session, paused
  with the Simulate's pause, ended at Stop or at a close mid-run. The GUI ends the run's screens
  and audio its group on the session's end, through the existing run lifecycle; the counter, the
  run-less tier and `EndUnboundScreens` are gone. A script with no run (a tool's, a test's) uses
  the shared tier again, as in the player.
- **Focus, as a Game tab:** Simulate makes the page's run the focused one (the one heard), and so
  does a click into its viewport; Stop keeps it, as a stopped Game tab does.
- **Its screens show:** a simulating page draws its run's screen tier over its viewport after the
  scene composes, as a Game tab does; they take no input (Simulate's pointer is the editor's).
- **Tests:** Engine.Script.Tests (the host's clock with and without a context; a scene in a run
  binds to its run's host, a loose one to the default, and the run's context is the one made);
  Editor.Scene.Tests (the page's run: carried by its scene, its host bound, in the registry, one
  session per Simulate with pause, a second page a second run, a close mid-run ending the session
  and the page's end taking the run out; Simulate taking the focus); Engine.GUI.Tests back to a
  run-less script on the shared tier.

## A scene's bus is its run's (2026-11-08)

- **The ruling:** a scene needs no bus of its own; it has its run's (the user, 2026-11-08). This
  closes the backlog item queued 2026-10-30 during the run spec ("the scene event bus, and
  whether it is needed"), possible once the scene page's Simulate became a run (above), so every
  scene that runs scripts has one.
- **The change:** `Scene::Events()` is its run's `IRun::Events()`, null outside every run;
  `Scene::SetEventBus`, `SceneManager::SetSceneEventBus` and the scene's borrowed pointer are gone,
  and a game and a scene page set only the run. `scene.events` reads as before to a script: in a
  game it was already the run's bus, and in a Simulate it is now the page run's, drained by the
  page as its own bus was.
- **The samples:** Lamplight, Snowline and PaperKid emit on `scene.events` and PaperKid and Sky
  Hopper on `run.events()`; none changes behaviour. No sample's tools use Simulate, and neither
  NativeSample nor the plugins touch the bus or the script host.
- **Tests:** Scene.Tests (a scene's bus is its run's, none outside a run, never drained by the
  scene); the script fixtures own a run instead of a bus; GameInstance.Tests (an adopted scene's
  bus is its new run's).

## An import no longer reads every asset (2026-11-08)

- **The bug:** the user's editor hung (the desktop offered to kill it) while an agent imported the
  flagship's scripts. Measured: every `asset_import` held the main thread about 7.4 s on a
  2014-asset project (`mainMs`), whatever the file. A re-import calls `SourcesCopyUsedByOther`
  (Pipeline.Importer), which walked every asset and deserialized each (`ReadObject`) to learn
  whether another shares the same copy under Sources/. The profiler did not see it: the work runs
  between frames, outside any scope; a 0.2 s ping of the editor's MCP showed the stalls.
- **The ruling:** the record knows its source (option iv of four, the user, 2026-11-08).
- **The change:** `ISerializable::SourceName()` (empty by default; `Asset` gives its `fileName`).
  A self-describing (XML) envelope's header carries it as `source` after the type, written by
  `WriteObject` and read by the database's scan with the type, so `Instance::SourceName()` needs
  no payload read; a binary envelope keeps its positional layout (cooked data names no sources).
  An envelope from before the header carried it is read once on asking, the name kept until the
  next write puts it in the header. The importer's check compares records' names.
- **Tests:** Content.Tests (the header names the source and the scan knows it without a payload
  read; an older envelope is read once, then kept; a binary one reads on asking).

## A script writes a struct-valued property (2026-11-08)

- **The bug:** found wiring the hometown's rift: `light.color = c` in AngelScript left the light's
  colour as it was. A struct-valued property (`Property<>` of a value type) read as a copy, and
  AngelScript's `obj.prop = value` on a handle-typed property assigns to the object the getter
  returns, so the write landed in the copy; `obj.prop.field = x` too; only `@obj.prop = @value`
  reached the setter. A `Nested<>` member returned a borrow, but `opAssign` replaced the borrow
  with the source's Variant instead of writing through it (and `saved = light.color` aliased the
  light). Luau set whole values through `__newindex` but lost field writes the same way.
  Sedulous's value-type registration fixes the whole value and still loses the field.
- **The ruling:** option A (the user, 2026-11-08): reads are handles over the member, found again
  through a re-resolving owner.
- **The change:** `Variant::ResolvingMember` (a member of what a re-resolving handle points at,
  found again through the owner's resolver on every access, at the member's offset);
  `Variant::Borrow` from a re-resolving owner (a component handle, which pins nothing and whose
  storage may move) gives one. `core::PropertyHandle` reads a writable value-struct or nested
  property as a member handle, `core::AssignValue` copies a value into or out of one (through
  whichever side owns its value, or a default-made one between two members), and
  `core::DetachedValue` hands a native by-value parameter the value rather than the handle. Both
  backends read properties through `PropertyHandle` and pass parameters through `DetachedValue`;
  AngelScript's `opAssign` uses `AssignValue` when either side is a member; Luau's `__newindex`
  copies one member into another. Read-only properties still read as values.
- **Tests:** Script.AngelScript.Tests (a value property whole and by field, a copy that stays apart,
  a nested member, one member from another); Engine.Script.Tests (a light's colour through its
  component handle, in AngelScript and Luau).

## Scripts add and remove components; destroyed entities let go (2026-11-08)

- **The ruling:** scripts add and remove components (the user, 2026-11-08), named
  `Component.addTo(entity)` and `Component.removeFrom(entity)` beside `Component.of(entity)`
  (the user's names: `add` read as adding the entity to the component). `addTo` hands back the
  component either way, made when the entity had none.
- **The change:** `foundation::script::ComponentAddTo<T>` (the manager's `AddDefaultComponent`,
  then `ComponentOf<T>`) and `ComponentRemoveFrom<T>` (`RemoveComponent`, whether there was one);
  `ComponentMethods<T>` registers the three together, applied through a new
  `TypeBuilder::Apply` on every component a script reaches (26 registrations in nine libraries,
  and the tests' Gadget). A component added at runtime is taken up as one added in C++ is: it
  initializes at the next frame's start, and each domain's system picks it up.
- **Found and fixed on the way:** nothing let go of what a component held when the component went.
  A destroyed entity, or a removed rigid body, left its body in the physics world (an invisible
  collider until the scene stopped), a character its character, a joint its joint; a destroyed or
  removed audio source left its voice playing. The physics component managers now hand a removed
  component's body, character or joint to the scene's physics system (`IPhysicsReleaser`, set while
  its world runs), which drops them at its next reconcile in dependency order (released joints,
  then the joint pass, which now also needs the joint's own body, then bodies and characters); the
  audio source manager hands a removed voice to the scene's audio system (`IAudioReleaser`), which
  stops it. A joint with no named target is bound to the nearest body above it, which its target
  check does not see leave: a joint holding a body released that reconcile now lets go first
  (`PhysicsWorld::JointHolds`, the foundation's answer from the joint's own two bodies) and is
  rebuilt at the next, on the next body above or the world (found by the Sedulous port; a
  use-after-free in Jolt otherwise). The other domains already let go: animation, the IK solvers and navigation through
  their managers, the GUI by sweeping hosts and texture roots no component used this frame,
  particles by owning their instance, replication by treating a networked entity's lost component
  as its despawn.
- **Tests:** Engine.Physics.Tests (a destroyed entity's and a removed component's body leave the
  world; a joint lets go before the body it holds; a joint without its own body drops; a character
  leaves with its entity); Engine.Audio.Tests (a destroyed entity's and a removed component's voice
  stop at once); Engine.Script.Tests (addTo adds and hands back, removeFrom takes off, in both
  languages; a rigid body added from script builds a body and its removal takes it out).

## Entity ids that two branches cannot both mint (2026-11-08)

- **The problem** (found by the Sedulous session; both engines; the users ruled: fix the seeding):
  every scene's id generator started from the same fixed seed and a load did not advance it, so two
  branches that each added an entity to one scene minted the same id, and a merge put one id on two
  entities in one file. Asset ids never had this: the content database seeded its generator from
  the OS's entropy.
- **The change:** `Random::FromSystemEntropy()` in Core (`sys::FillEntropy`; the clock and a count
  should the OS refuse), which a scene's id generator now starts from; `Scene::SeedIds(seed)` makes
  the sequence repeat for a test pinning ids, a replay or a seeded level. The content database
  uses the same helper in place of its own `std::random_device` code.
- **Tests:** Core.Tests (two entropy-seeded generators differ); Scene.Tests (two scenes' first ids
  differ; seeded alike, they match).

## One-shots, clip lengths and crossfades for animated entities (2026-11-08)

- **Why:** the flagship's dialogue wanted a Lumin to hop or flinch for a beat and then stand again,
  and a script could not: `SceneAnimation` had no clip length, a clip's looping was its asset's, and
  nothing returned an entity to its own animation. Every clip change snapped. The user's rule: what
  a script cannot do is an engine gap, and the fix stays generic.
- **The design** (from Flax's `PlaySlotAnimation`, Godot's OneShot node, ezEngine's simple
  animation modes): a `foundation::animation::PoseOverlay` that each player (the single-clip one and
  the graph's) lays over its own pose before its pose modifiers: a one-shot blended in and out with

  no graph authoring and works for both kinds of animated entity; a one-shot is full-body and moves

- **The surface:** `SceneAnimation.playOneShot` (with speed, blend times, loops), `stopOneShot`,
  `isPlayingOneShot`, `clipLength`, `setClip(entity, clip, blendSeconds)`
  (`AnimationPlayer::CrossFadeTo`). A one-shot's end reaches the entity's behaviours as
  `onAnimationFinished(clip)`: the animation subsystem tells its `IAnimationListener`s, and
  `ScriptAnimationBridge` in Engine.Integration delivers through the new
  `ScriptSubsystem::DeliverEvent` (the queue physics contacts use, renamed `EnqueueHandler`), so
  Engine.Animation gains no script dependency.
- **Tests:** Animation.Tests (the overlay: in, hold, out, once though the clip loops; loops, until
  stopped, a stop's blend; a crossfade; a graph's pose); Engine.Animation.Tests (the manager starts

## A tween moves a property code set (2026-11-09)

Found in the flagship's playtest: a panel the game made, its `opacity` set by script, never faded
with `tween("opacity", ...)`, in either direction (the game's scene-change cover never showed on
the way out of a map; its arrival "fade" was the cover being destroyed).

- **Cause:** code setting opacity (`Node::SetAlpha`) pins the style slot, as an inline style, so
  the sheet leaves it alone; a tween of a property a sheet names went through the style's motion
  layer, which the style applier skips for a pinned slot (StyleApplier's `free(SlotOpacity)`).
- **Fix:** `Tween::Bind` writes the reflected property, as on a plain node, when code pinned the
  property's slot (found by `StyleSlotProperty`): the tween moves code's value from where it is,
  and code can set it again after. A property code never set still moves over the cascade.
- **Tests:** GUI.Tests (a code-set opacity tweens up and down through its setter, code sets it
  after; a sheet's still moves over the cascade).

## Prefabs as resources: the mirror begins (2026-11-09)

The prefab-resources plan (Sedulous's spec, built there first) mirrored commit by commit, in its
order.

- **A, a game run from its project folder spawns prefabs and loads scenes:** its content database
  is the cooked one and its scenes and prefabs are the sources'. DefaultApplication gains
  `SetSceneDatabase`/`SceneDatabase()` (the content database when unnamed: the editor, an exported
  game); spawns (`OnSystemsReady`, `PointSpawnersAtScenes`), the replicated-spawn resolver and a
  script's `loadScene`/`loadSceneAsync` read it, and the player names its scene database. Wider
  than Sedulous's: our script scene loads read the cooked database too. Tests: Engine.DefaultApp.Tests
  (spawns from the scene database, not the cooked one; with one database, from it).
- **B1, a content database refreshes what changed on disk:** `ContentDatabase::Refresh(paths,
  ContentChanges&)` brings the index in line with envelopes and data streams a watcher reports: an
  appeared envelope registered (its folders' groups made), a changed one read again (the same
  identity and type keep their record, its source name refreshed; another replaces it), a gone one
  dropped and freed (another record of the same guid takes the index), a data stream's change
  reported for its record, an unreadable envelope kept and reported for a later try. The scan and
  the refresh share one header reader. Tests: Content.Tests (added under new folders, changed and
  kept live, a data stream, cut inside its header and read whole again, another identity at the
  same path, removed, unknown paths).
- **B2, the editor watches Content/:** `editor::ContentWatcher` (Editor.Project) sweeps Content/
  (size and modified time), acts on a path once it looks the same on two looks, and hands one
  poll's settled paths to one `ContentDatabase::Refresh`, holding them while others still change
  (up to five polls); an unreadable envelope is tried again each poll. The editor's own writes are
  taken in silently: `NativeFileSystem::OnWritten` names each path a write touched, and the project
  keeps them while a watcher listens. The cook service polls about once a second and at once when
  the window regains focus, never while a reader has the databases, cooks what cooks, and fires
  `OnContentChanged`; the session hands it to `EditorContext::ApplyContentChanges`, which reloads
  or warns pages (as before) and, for a removed record, `NotifyAssetDeleted`: the page stays open,
  marked unsaved and told, and `EditorContext::SavePage` (now under every page save) puts the
  record back at its place with its identity first, refusing when another asset took the place.
  Our stat's times are whole seconds (Sedulous's are ticks): a rewrite of the same size within the
  same second as a look is not seen until the file changes again. Tests: VFS.Tests (every write
  names its path), Editor.Core.Tests (settling, a burst as one refresh, the hold limit, the
  editor's own writes, a removal and where it lived, an unreadable envelope, the cook service's
  polling, a deleted asset's page), Editor.Scene.Tests (a replaced scene reloads a clean page and
  warns a dirty one, a deleted one's page stays and its save writes it back, the page's own save
  keeps its history).
- **C1, a script's asset properties are export references:** a script property holding an asset is
  never bound by the scene (the script binds it when it uses it), so a prefab, clip or material
  named only by a behaviour's or a Level's override was left out of a pruned export.
  `SceneSystem::CollectUnboundReferences` reports what a system names without binding; the script
  manager and the scene script system report their asset-kind overrides
  (`CollectOverrideAssetIds`), and `ScanSceneReferences` adds them beside the binds. Tests:
  Engine.Composition.Tests (a behaviour's and the Level's asset overrides reached, an entity
  override not).
- **C2, a placed prefab's overrides are references too:** a placed instance stays parked at load,
  so an asset named only by one placement's override was missed (the gap Sedulous found in both
  engines). `ScanSceneReferences` takes the placed ids, then spawns the parked instances from the
  same database (`ResolveScenePrefabs`, nested ones one level at a time) before it collects.
  Tests: Engine.Composition.Tests (a placement's override reached, the placed prefab's id still
  reported).
- **1, a layered database and a factory that reads an authored record:** a prefab document is an
  authored record the cook never builds, so a manager reading the cooked database cannot see it.
  `LayeredContentDatabase` (Content) puts a fallback (the sources) beneath a primary (the cooked
  products): the primary answers first, the fallback only for a record whose stored type its
  predicate accepts; the view names no type. A factory declares its stored type authored
  (`IResourceFactory::ReadsAuthoredRecord`, default false), and `ResourceManager::ReadsAuthoredRecord`
  answers from the factory reading that type, asked at each lookup. Tests: Content.Tests (the
  primary wins, a declared type falls through by id and path, an undeclared one does not),
  Resource.Tests (only an authored factory's record binds from the sources; the cooked one wins;
  the answer follows the factories).
- **2, a prefab is a resource:** `PrefabFactory` (Scene.Resource) loads the `PrefabDocument`
  record's scene stream into a `PrefabResource`, a runtime type of its own: its id, name and the
  payload's bytes as stored, text or binary, reached through `OpenPayload` (a borrowed
  `PrefabPayloadStream`). It declares its record authored, refuses any other record type (a scene
  is never loaded through a prefab reference), and loads on a worker whole. `PrefabPayloads` opens
  loaded prefabs for a spawn, binding each through the manager, with a resolver for nested ones; a

## Scene facades are properties of the scene (2026-11-09)

- **The decision:** the 0.1 backlog's "Scene facades as scene properties" (user 2026-10-09; struck
  today). A scene facade's `of(scene)` could not fail: it only wrapped the scene it was given, so
  it was a property spelled as a lookup, and `scene.` listed none of them. They are properties
  now: `scene.physics`, `scene.animation`, `scene.audio`, `scene.render`, `scene.particles`,
  `scene.splines`, `scene.scripts`, `scene.prefabs`, `scene.debugDraw`, `scene.environment`,
  `scene.postProcess`, beside `scene.events`; every `of(scene)` is gone (no forwarders: nothing
  outside our repos uses them before 0.1). A component's `of(entity)` stays: it is a lookup that
  can answer null.
- **How:** the script `Scene` lives in Foundation (Script.Facades) and the facades in the engine
  domains above it, so its reflection cannot name them. Core reflection gained `ExtendProperty`:
  a module adds a computed read-only property to a value type another module reflected, from a
  free getter `R (const T&)` (or one returning a resolving Variant, with its declared type, as
  the render settings need). It re-points the type's property list at startup registration,
  before anything binds the type, so the AngelScript and Luau bindings, the declarations and
  `script_api` see an ordinary property with no case of their own. Script.Facades wraps it as
  `ExtendScene<&Getter>("name")`, which registers Scene first; each domain calls it beside
  registering its facade type, from the getter that was its `of` (`ForScene`, C++ only now).
  `scene.prefabs` needs none of it: it is a computed property of Scene, as `events` is. No module
  dependency changed.
- **Moved with it:** the sample games' scripts, the engine tests' scripts, the scripting guide (a
  section on the scene's properties), the systems docs that named an `of`, the changelog. Tests:
  Core.Tests (an extension reads as a computed property; a repeat is harmless; a taken name, a
  second name for one getter and an unreflected type are refused; a Variant getter's declared
  type), Engine.Script.Tests (every facade through the property, on both backends where they
  were), Integration.Mcp (the samples cook).

## Thumbnails of an uncooked project wait for the cook (2026-11-10)

- **The report** (user, 2026-11-10, from a downloaded sample, which ships uncooked): on

  cooked state of what it shows, a running cook waits, a waiting job caches nothing and runs again),

## Stability: saves replace a file whole (2026-11-13)

- **Fixed:** `NativeFileSystem::Save` (every content database write: assets, scenes) and Core's
  `WriteFile` (sources, settings, paks, zips, the model viewer) truncated the file and wrote over

## Stability: the event bus may change while it delivers (2026-11-13)

- **Fixed:** `EventBus::Unsubscribe` removed from the array the drain was walking, so a handler

## Stability: a run defers what its scripts destroy (2026-11-13)

- **Fixed:** destruction waited only inside `Scene::Update` and `SceneManager::Update`. Scripts
  also run in the fixed step, the run bus drain, the network pump and destroy hooks, where a
  destroy was immediate: a scene destroyed from its own `onFixedUpdate` or a bus handler freed the
  scene on the stack, and a destroy hook destroying a sibling destroyed it inside the walk of the
  first. `foundation.run` gains `RunMutations` (`IRun::Mutations`): whoever runs a run's scripts
  opens a `Scope`, work asked for meanwhile is queued under its owner, and the same caller flushes
  once the scope closes; an owner going away cancels its work, so no queued work reaches a freed
  scene. The scopes: `SceneManager::BeginFrame` and `Update`, `GameInstance::TickScript`,
  `RunBase::DrainEvents` (the game's and the scene page's run bus) and the network pump per run.
  `Scene::DestroyEntity` waits while the scene steps (Update, now also the fixed steps and
  destroy hooks: `ProcessPendingDestroys` loops until none is left) or its run defers; an
  immediate destroy goes through the same loop, so hooks destroy after, not inside.
  `SceneManager::DestroyScene` waits during `BeginFrame` too and while its run defers, and a
  scene asked twice is destroyed once.
- **Open:** component removal is not queued. A script's `removeFrom` followed by `of` sees the
  component gone at once (a test asserts it); queued, it would stay until the flush. Its
  re-entrancy (the index reused after the hook) is S3's.
- **Tested:** Run.Tests (scopes nest, order, work queued by work, cancel before and during the
  flush; the run bus drained deferred), Scene.Tests (a destroy in the fixed step, a hook
  destroying a sibling, a destroy waiting for the run and cancelled with its scene; a scene
  destroying itself from its fixed step and from a bus handler, asked twice).

## Stability: the transport handshake takes a cookie, and data carries the token (2026-11-13)

- **Gate:** the budgets phase closed green on clang, gcc and clang-shared (204 of 204 each).
- **Fixed:** `ReliableTransport` made a connection, and a Connected event and a peer, for any

## Stability: a window on reliable messages, and a cap on the queue (2026-11-13)

- **Fixed:** the sender sent every queued reliable message and the receiver buffered any early
  arrival, however far ahead, so a peer could park up to 32767 messages in another's reorder
  buffer, and past 32768 in flight `SeqGreater` no longer told older ids from newer. A sender
  that stayed connected while its peer acked nothing queued without end. Now `kReliableWindow`
  (1024, a protocol constant, since both ends must agree) bounds both: the sender sends no id past
  its oldest unacked one plus the window, and the receiver keeps no early arrival past its next
  expected id plus it. Every id below the sender's oldest unacked one has reached the receiver,
  so a sender inside its window is inside the receiver's: the receive check drops only what a
  sender keeping to the window never sends (packets are acked whole, so a dropped message would
  otherwise be lost). `ReliableConfig::maxQueuedReliable` (16384) caps the unacked queue: a send
  past it disconnects the peer, with a Disconnected event and a warning.
- **Tested:** Net.Tests (ten queued to a silent peer at a cap of ten, the eleventh disconnects;
  3000 queued to a silent peer over 3 s, no id past 1023 sent; a crafted message 1029 ahead is not
  kept, the 1029 before it arrive, and resent inside the window it arrives). All three fail on the
  old transport. The clang battery: 204 of 204.

## Stability: a stream whose peer stops reading fails (2026-11-13)

- **Fixed:** `PlainStream::Send` and `TlsStream::Send` took every byte into the unsent buffer and
  reported it sent, so a peer that never read (a stalled tab on the WebSocket gateway, a slow
  HTTP server) grew the sender's memory without end. A stream that would hold more than
  `INetByteStream::kMaxUnsentBytes` (8 MB) unsent now fails, Failure "the peer stopped reading (N

## Stability: Luau boxes are tagged, self is checked, newproxy is gone (2026-11-13)

- **Fixed:** the Luau backend read every userdata as a `Variant` box (`lua_touserdata`), and

  now takes a self of its type or one derived from it (`SelfOf`), and a method says "called on a
  value of another type".
- **Tested:** Script.Luau.Tests (newproxy is nil; a same-type call works; `Compass.opposite` on a

## Stability: a Luau call runs under a time and memory budget (2026-11-13)

- **Fixed:** nothing bounded a script call: a loop that never ended hung the game, a top level that
  never ended hung its load, and one that allocated without end took the process's memory.
  `IScriptManager` gains `ScriptBudget` (`callSeconds` 5, `heapBytes` 512 MB) with `SetBudget` and
  `Budget`. In the Luau backend every entry into the VM from the engine (`VmCall`, at each
  `lua_pcall` and `lua_resume`) starts the clock when it is the outermost, so a coroutine's wait

  fails that call. The state is made with `lua_newstate` and an allocator that refuses a block
  growing the heap past `heapBytes`, which the VM raises as out of memory in the call that asked.
  The callbacks' userdata is now the context, which holds the attached debugger. The AngelScript
  backend stores the budget; its enforcement is the next entry.
- **Tested:** Script.Luau.Tests (`while true do end` at 0.5 s stops after 0.50 s with the budget
  message and the context answers the next call; two 0.3 s calls fit a 0.5 s budget; an endless

## Stability: AngelScript calls run under the budget (2026-11-13)

- **Fixed:** in the AngelScript backend nothing bounded a call either. The manager's
  `ExecuteClock` starts the budget's clock at the outermost Execute, as Luau's `VmCall` does, and
  a line callback (`BudgetLineCallback`, armed on each pooled executor, coroutine and constructor
  run; the debugger's callback, when it is armed instead, checks the budget first) reads it every
  256 lines and aborts the context past `callSeconds`; an aborted call reports "script call
  stopped: ran past its N s budget". Recursion that never ends fails its call ("Stack overflow")
  at `asEP_MAX_CALL_STACK_SIZE` 20000 nested calls (Luau's own limit) and a 1 MB data stack,
  instead of growing until memory runs out: the data stack alone did not stop a recursion with
  small frames, which ran on until the time budget stopped it. AngelScript allocates through
  process-wide functions, so `heapBytes` is Luau's alone (said in `ScriptBudget`).
- **Changed:** global variable initializers ran inside `Build`, on the engine's own context, where
  nothing could stop one that never returned, and so the cook's `CompileToBlob` ran them.
  `asEP_INIT_GLOBAL_VARS_AFTER_BUILD` is now off; each load (source, behaviour module, bytecode)
  runs them on a budgeted context (`InitGlobals`, `ResetGlobalVars`), its failure a Runtime error.
  The cook compiles without running script, as the Luau cook always did, so a faulting
  initializer now fails the game's load of the script rather than the cook (the pipeline test
  that pinned the cook failure now pins that the cook passes).
- **Decided (revised):** spec Decided 7 had the cook and `script_validate` run a script's top level
  under a small budget. Per the user (2026-11-13), `Check` and the cook stay compile-only and the
  runtime budget is the bound; the spec is amended.
- **Tested:** Script.AngelScript.Tests (an endless loop in a method stops after 0.50 s at a 0.5 s
  budget with the budget message, and the next call works; endless recursion fails with "Stack

  `CompileToBlob` and `Check`, fails its load with the budget message, and an initializer that
  returns still sets its global). Script.Pipeline.Tests updated as above. The clang battery: 204
