## After a survey of the engine: the graph's hazards, CI on Windows, licences (2026-10-31)

A survey of our own code, read against what it does; what it found, fixed:

- The render graph ordered passes by read after write only, so the sort could move a write past
  an earlier reader of the same resource, or two writes past each other. Two tests showed both;
  `BuildDependencies` now adds write-after-read and write-after-write edges (subresource-aware,
  pointing back in declaration order, so the declared order always satisfies them). Checked
  first whether today's frames hit it: the six samples played with a probe of every reversed
  pair, and the one pattern reported (Shader Gallery's probe capture, `forward` before `sky`)
  was across cube faces, separate array layers, so no shipped frame was wrong.
- Windows CI: the `scriptContext` rename made one name shadow another in the backend battery
  (MSVC C4456 under /WX), and the model viewer's shared build could not link
  `OpenModel::kRecordName` (data across a DLL boundary needs ENGINE_EXPORT_DATA).
- Licences: cgltf, miniaudio, stb, ufbx (from their headers or tag), DXC, Naga, Tint and
  wgpu-native (from their tags) now have their licence files beside them, and
  `THIRD-PARTY-NOTICES.txt` (cmake/ThirdPartyNotices.cmake) goes beside every player, editor and
  model viewer and, through the runtime-libs list, into every template and export; the export
  test now runs on the host template and checks it.
- Stale comments: the shadow system (four cascades and a two-layer atlas, not one map), the
  cluster kernel (real, not a stub), the render graph (no aliasing within a frame), the script
  debug seams (both backends debug and cook bytecode), game-native N6 (built). Onboarding: Clang
  21 as the floor (18 fails), two scripting backends, SDL3 from source.
- Backlogged: transient reuse within a frame, input rebinding in the engine, and discussions of
  script reload state, editor testing and native state migration.

## Plugins X0: the manifest and the package layout (2026-11-03)
